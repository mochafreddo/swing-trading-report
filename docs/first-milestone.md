# 첫 보고서 구현 계획

첫 구현의 결과물은 실제 데이터에 근거한 장전 보고서 한 편과 검증 기록이다. 2026-09-10에 사용자가 [요구사항](requirements.md)과 이 문서의 첫 마일스톤 범위·완료 기준을 최종 확정했다. 현재는 문서만 작성했으며 실제 API 접근, 보고서 생성, 텔레그램 전송과 예약 실행은 수행하지 않았다.

## 구현 순서

### 1. 실제 데이터로 계산할 수 있는지 확인한다

기존 KIS·토스 API에서 필요한 종목 정보, 시가총액, 정규장 일봉과 거래대금을 얻을 수 있는지 확인한다. 거래일, 세션 범위, 금액 단위, 수정주가 처리와 조회 범위를 확인하고, 재현에 필요한 데이터 기준 시각과 출처를 기록한다.

합의한 종목군 전체를 탐색 대상으로 구성한다. 개별 종목의 데이터 부족은 보류로 표시하되, API가 반환한 상위 일부 종목만으로 전체 탐색을 대신하지 않는다. 전체 탐색 범위를 확보하지 못하면 확인 결과를 기록하고 사용자와 범위 변경 여부를 결정한다.

실적 일정과 기업 뉴스·공시의 근거 자료도 첫 마일스톤부터 자동 수집한다. 기업 IR 등 확인 가능한 출처에서 자료와 출처·확인 시각·대상 날짜를 함께 확보하며, 보고서 생성에 필요한 자료를 사람이 확인해 입력하는 방식으로 자동 수집을 대체하지 않는다. 확정 실적 일정의 인정 기준과 뉴스 조회 기간은 [요구사항](requirements.md)을 따른다. 추가 유료 시장 데이터 구독 없이 자동 수집할 수 있는 출처와 검증 방법은 실제 연동 전에 확인한다.

데이터 확보와 계산 규칙 검증을 첫 작업으로 삼는다. 필요한 자료를 얻지 못하면 확인한 범위와 부족한 항목을 기록한다. 기준을 만족하지 않는 자료로 매수 후보를 만들지 않는다.

### 2. 후보와 가격 계획을 계산한다

종목 탐색, 선정 조건 판정, 후보 순위와 가격 계획 계산은 코드로 재현한다. 합의한 종목군과 돌파 규칙을 적용하고 후보별 선정·제외·보류 사유를 남긴다. 지표의 기준 거래일, ATR 초기값과 계산 방식, 동순위 처리 등 세부사항을 고정하고 작은 검증 사례로 확인한다.

보고서에는 후보 최대 3개, 조건 충족 후보 없음, 평가 불가를 구분해 표시한다. 검증된 탐색 범위와 보류된 범위를 함께 기록한다. 발행 당시의 근거와 예시 가격을 보존해 이후 후보 경과를 비교할 수 있게 한다.

### 3. AI 설명을 붙이고 보고서 한 편을 검토한다

공개 자료와 계산 결과를 바탕으로 선정 이유, 기업 뉴스·공시의 위험 요약, 학습 포인트를 생성한다. 사실 설명의 출처와 기준 시각을 확인한다. AI가 선정·순위·계산 가격을 변경하지 않는지 검증하고, 사용량과 비용을 기록한다.

AI 설명을 만들지 못해도 필수 데이터가 검증되었다면 기본 보고서를 만든다. 보고서 생성은 코드로 수행하며 텔레그램 개인 채팅에서 읽을 형태로 정리한다. 실제 거래일의 정규장 개장 60분 전에 단건 전송하고 내용을 검토한다. 첫 단건의 실행은 수동으로 시작할 수 있다. 다른 시각에 보내는 보고서는 미리보기로 구분하며 정시 전달 완료로 인정하지 않는다.

첫 단건 전송 전에 전송 결과 불명확 상황을 검증한다. 자동 재전송 중단, 사용자 수신 확인과 미수신 시 수동 재전송은 요구사항의 처리 정책을 따른다.

## 첫 구현의 완료 기준

- 실제 데이터에 근거한 보고서 한 편과 그 결과를 재현할 수 있는 기록이 있다.
- 합의한 종목군 전체를 탐색 대상으로 구성했고, 평가한 범위와 개별 종목의 보류 사유를 기록했다. 실적 일정과 뉴스 근거를 자동 수집한 결과와 출처를 확인했다.
- 선정·순위·가격 계산과 AI 설명의 근거를 검토했다.
- 후보가 있는 경우, 조건 충족 후보가 없는 경우, 평가 불가인 경우를 구분하는 검증 사례가 있다. 검증용 사례와 실제 보고서를 구분한다.
- 검증된 데이터에서 나온 조건 충족 후보 없음은 실제 보고서의 정상 결과로 인정한다. 이 경우 후보 설명과 가격 계획은 별도 검증 사례로 확인한다. 전체 평가 불가인 보고서만으로는 완료하지 않는다.
- AI 설명의 정상 생성과 장애 처리를 각각 확인했다. 실제 보고서에서 AI 설명이 빠졌다면 별도로 정상 생성과 근거 검토를 확인해야 한다.
- 잘못된 시세, 실적 일정 미확인·예상 일정만 존재, AI 장애, 전송 결과 불명확에 대한 작은 실행 가능한 검증이 있다. 검증이 막으려는 오류를 의도적으로 재현한 상태에서 같은 검증이 실패하는 결과도 남긴다.
- 실제 거래일의 정규장 개장 60분 전 텔레그램 단건 전송 결과와 사용자의 내용 검토 결과가 기록되어 있다.

실제 연동이나 전송을 확인하지 못한 부분은 미완료로 기록한다. 문서나 검증용 데이터만으로 실제 보고서의 완료를 주장하지 않는다.

## 후속 단계

보고서 한 편을 검토한 뒤 Mac의 예약 실행과 후보 경과 기록을 연결한다. 실행 지연, 복구 시한과 AI 예산 소진을 검증하고, 예약 실행에서도 전송 결과 불명확 처리 정책이 유지되는지 확인한 뒤 10거래일 시험 운영을 진행한다. Mac 지연 처리 검증은 예약 실행을 켜기 전에 완료한다.

실제 거래 기록의 토스증권 자동 수집은 이후 단계다. 앱에서 직접 주문한 미국 주식 거래의 조회 가능 범위를 확인한 뒤 구현한다. 거래당 수량 계산, 개인 계좌 자료를 활용한 AI 복기와 실제 보유 종목의 기간 경과 점검·청산 기준도 후속 범위다.
