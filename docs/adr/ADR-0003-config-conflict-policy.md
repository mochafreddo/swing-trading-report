## ADR-0003 — 설정 충돌 정책: config.yaml / .env 중복 키 금지 (Fail-Closed)

상태: 채택(Accepted)  •  날짜: 2026-02-08

### 배경

- ADR-0001은 설정 우선순위를 `config.yaml → .env → CLI`로 정의했습니다.
- 하지만 PRD의 원칙은 “단일 소스(Single Source of Truth)”이며, `.env`와 `config.yaml`에 동일 키를 중복 정의하면 실행이 불확실해지고(실험값/기본값 섞임), 운영 실수 가능성이 커집니다.

### 결정

- `.env`/환경변수와 `config.yaml`에 **동일 설정 키를 동시에 정의하는 것을 금지**한다.
- 중복이 감지되면 **즉시 실패(fail-closed)** 하며, 충돌한 키 목록을 출력한다.
- ADR-0001의 우선순위 규칙은 다음처럼 해석한다.
  - 키가 “한 곳에만” 정의되어 있을 때는 `config.yaml → .env → CLI` 순으로 로드/적용한다.
  - 키가 양쪽에 동시에 있으면 오류로 간주한다(우선순위로 덮어쓰지 않음).
- 시크릿(KIS AppKey/AppSecret 등)은 기존 정책대로 **`.env`/환경변수에만** 둔다.

### 결과/영향

- 장점
  - 설정의 출처가 명확해지고 재현 가능성이 높아집니다.
  - “로컬에서만 동작하던 값”이 의도치 않게 기본값을 덮어쓰는 사고를 줄입니다.
- 단점
  - `.env`로 손쉽게 override 하던 패턴은 불편해질 수 있습니다(필요 시 `config.local.yaml` 등으로 해결).

### 대안 검토

- 기존대로 override 허용: 편하지만 설정 드리프트/모호성 증가
- allowlist 방식(일부 키만 override 허용): 정책이 복잡해지고 문서/검증 비용 증가
