## ADR-0007 — v1.1 현재 아키텍처 기준선(report_index/관리자 인증)

상태: 채택(Accepted)  •  날짜: 2026-02-23

대체 대상: `ADR-0006-open-decisions-v1.1.md`

### 배경

- `ADR-0006`은 v1.1 초기 가정(인덱스 미도입, 인증 미도입)을 기록했지만, 실제 구현은 이와 다르게 발전했다.
- 현재 구현에서 리포트 목록/검색은 `report_index`를 핵심 경로로 사용한다.
- 웹 UI는 관리자 세션 인증과 same-origin/로컬 요청 검증을 기본 보안 경계로 채택했다.
- 아키텍처 문서와 운영 문서의 전제를 일치시키기 위해 현행 기준 ADR이 필요하다.

### 결정

1) 리포트 목록/검색 인덱스

- 리포트 목록/검색의 기준 저장소는 Supabase Postgres `report_index`로 한다.
- Python 파이프라인(`scan`/`sell`)은 Storage 업로드와 함께 `report_index` upsert를 수행한다.
- GitHub Actions 실행에서는 Storage 업로드 또는 `report_index` upsert 실패를 fail-closed로 처리한다.

2) 인증/권한 및 런타임 상태

- 웹 보호 API(`reports`, `holdings`, `run`)는 관리자 세션 인증을 필수로 요구한다.
- same-origin 검증과 로컬 요청 강제를 기본값으로 적용한다.
- 로그인 시도 제한 상태 등 단기 런타임 상태 저장소는 `runtime_state`를 기본으로 사용한다.

3) 캔들 캐시 범위

- Supabase Postgres 캔들 캐시 테이블은 v1.1 범위에서 계속 미도입으로 유지한다.
- 로컬 `data/` 캐시는 API 실패 시 폴백/증분 갱신 보조 수단으로 유지한다.

### 결과/영향

- 장점
  - 문서와 코드의 단일 진실원이 일치해 운영/개발 의사결정 혼선을 줄인다.
  - 리포트 조회 성능 및 검색 일관성을 `report_index` 중심으로 관리할 수 있다.
  - 웹 운영 보안 경계(인증/요청 검증)가 명시적으로 고정된다.
- 비용/리스크
  - `report_index` 스키마/업서트 경로의 안정성이 서비스 가용성에 직접 영향을 준다.
  - 인증 경계와 `runtime_state` 저장소의 장애 대응(runbook/관측)이 필요하다.

### 재검토 트리거

- `report_index` 조회 성능 저하 또는 upsert 실패율 상승
- 공개 배포/멀티유저 요구로 인증 모델(예: SSO, 역할 기반 권한) 재설계 필요
- 캔들 API 호출량이 증가해 Postgres 캐시 도입 타당성이 생김
