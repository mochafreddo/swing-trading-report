### [MAJOR] Non-finite candle(`NaN`) cache poisoning 가능: 날짜만 fresh면 재사용
- Evidence:
  - 파서가 빈 값/파싱 실패를 `NaN`으로 변환(`sab/data/kis/quote.py:670-676`, `:703-709`).
  - 파이프라인 정규화는 “미완성 tail 제거(날짜)”만 수행(`sab/market_data_pipeline.py:346-374`), 수치 finite 검증 없음.
  - cache staleness 판단도 날짜 기준(`sab/market_data_pipeline.py:261-299`).
  - `stale_sessions==0`이면 캐시 즉시 적용(`sab/market_data_pipeline.py:594-606`), fetch 성공 데이터도 그대로 저장(`:689-694`).
  - 이후 평가 단계에서야 non-finite로 탈락(`sab/signals/evaluator.py:74-89`, `:223-228`).
- Impact:
  - 한 번 오염된 캐시가 반복 재사용되어 같은 종목이 계속 system issue를 발생시킬 수 있습니다.
  - 장애 원인이 data-source인지 cache인지 분리가 어려워 운영 비용이 증가합니다.
- Recommendation:
  - 캐시 저장 전/사용 전 공통 finite validator 추가(`OHLCV` 최소 필드).
  - 비정상 봉은 drop하고, 최소 히스토리 미달이면 해당 티커를 즉시 실패로 마킹(오염 캐시 미저장).
  - 회귀 테스트: malformed provider row -> 캐시 미저장 + 다음 실행 재fetch 보장.
  - Patch 방향:
    1. `market_data_pipeline`에 `_sanitize_finite_candles()` 추가.
    2. `_trim_incomplete_candle_tail()` 결과에 sanitize 적용.
    3. sanitize 결과 empty/too-short 시 `runtime.failures` 기록 후 skip.
- Effort: M. Confidence: High.
