# 첫 버전의 요구사항

이 문서는 대화에서 합의한 첫 버전의 요구사항을 기록한다. 요구사항 정리는 완료했으며, 전체 명세의 최종 확인을 거쳐 구현을 시작한다. 실제 연동으로 확인할 항목은 별도로 표시한다.

## 목적

미국 주식의 매수 후보를 찾는 일을 돕는다. 사용자가 일반적인 스윙 트레이딩을 배우는 목적도 함께 충족한다.

## 합의한 범위

- 미국 주식을 대상으로 한다.
- 첫 후보 선정 유형은 돌파로 한정한다.
- 전날 정규장 종가로 돌파가 확인된 종목을 선정한다. 당일 진입 조건과 가격이 너무 올라 진입을 보류할 조건을 함께 제시한다.
- 초기 돌파 규칙은 전일 종가가 그 이전 20거래일의 최고가를 넘고, 전일 거래량이 그 이전 20거래일 평균의 1.5배 이상이며, 전일 종가가 50일 이동평균 위에 있는 것이다. 이 규칙은 학습·검증을 위한 초기 가설이다.
- 토스에서 거래 가능한 NYSE·Nasdaq 상장 보통주 중 시가총액 100억 달러 이상, 최근 20거래일 평균 거래대금 5,000만 달러 이상인 종목을 탐색한다. 필요한 데이터의 단위와 조회 범위는 실제 연동 단계에서 검증한다.
- 조건을 통과한 후보는 평소 대비 거래량 증가 배율 순으로 정렬한다. 같은 배율이면 최근 20거래일 평균 거래대금이 큰 종목을 우선한다.
- 보고 당일을 포함한 향후 5거래일 안에 실적 발표가 예정된 종목은 제외한다. 발표가 장전인지 장후인지와 관계없이 해당 날짜를 적용한다. 실적 일정을 확인하지 못한 종목은 보류하고 이유를 표시한다.
- 미국 주식 정규장 시작 60분 전에 텔레그램으로 장전 보고서를 제공한다.
- 매수 후보는 최대 3개를 자세히 설명한다. 조건을 충족하는 종목이 없으면 후보를 제시하지 않고 그 이유를 설명한다.
- 정보 정리, 매매 계획 제안, 조회·점검·기록을 지원한다.
- 첫 매매 계획은 진입 조건·가격 범위·손실 제한 기준·이익 실현 기준을 포함한다. 투자금에 맞춘 수량 계산은 거래당 손실과 전체 보유 위험 기준을 정한 뒤 추가한다.
- 후보와 당시 선정 근거를 저장하고, 다음 장전 보고서에서 후보 경과를 점검한다. 후보 선정 사실만으로 실제 매수나 체결을 가정하지 않는다.
- 주문은 사용자가 직접 실행한다.
- 사용자는 KIS API를 활용할 수 있고 토스증권 계좌와 API를 사용한다고 밝혔다. 실제 API 접근 권한과 데이터 제공 범위는 아직 검증하지 않았다.

## 매매 계획과 후보 경과

정규장 일봉의 ATR(14)를 사용한다. 진입 검토 구간은 전일 종가부터 전일 종가에 0.5ATR을 더한 가격까지이며, 구간 밖의 가격에서는 진입을 보류한다. 초기 손실 제한 기준은 돌파 기준선에서 1ATR을 뺀 가격이다. 이익 실현 기준은 실제 진입가에 2R을 더한 가격이며, 1R은 실제 진입가에서 초기 손실 제한 가격을 뺀 주당 계획 위험이다.

보고서에는 전일 종가를 기준 진입가로 사용한 계산 예시와 산식을 표시한다. 실제 진입가가 다르면 1R과 이익 실현 기준을 다시 계산한다. 손실 제한 기준은 실제 체결가격이나 최대 손실을 보장하는 값이 아니다. ATR과 가격 배수는 학습·검증을 위한 초기 가설이다.

진입 계획은 해당 정규장 하루 동안 유효하다. 후보 경과는 최대 20거래일 관찰하며, 같은 종목이 다시 선정되면 새 날짜의 계획으로 기록한다. 일봉만으로 진입·손실 제한·목표 가격의 도달 순서를 알 수 없으면 판정 불가로 남긴다. 후보 경과에서 실제 거래의 체결이나 수익률을 가정하지 않는다.

후보 경과에서는 보고서 발행 당시 전일 종가로 계산한 예시 가격을 고정해 이후 일봉과 비교한다. 예를 들어 고가가 예시 목표 가격 이상이었는지를 기록하며, 이를 사용자의 목표 달성으로 표현하지 않는다. 관찰 기간이 끝나면 해당 후보의 경과 기록을 종료한다. 사용자의 실제 보유 종목에 대한 기간 경과 청산 규칙은 별도로 정한다.

## AI 활용

OpenAI API로 학습 설명과 출처가 있는 기업 뉴스·공시의 위험 요약을 생성한다. 선정 조건 판정과 가격 계산은 코드가 담당한다. AI는 조건을 통과한 후보의 선정 이유, 주의할 사건과 계획이 무효가 되는 상황을 설명하며, 근거를 확인하지 못한 내용은 확인 불가로 표시한다.

AI 해석은 후보의 선정·순위·계산 가격을 변경하지 않는다. 뉴스 해석에서 발견한 위험은 사용자 검토 사항으로 표시한다. 뉴스 설명의 확인 불가와 필수 선정 자료인 시세·실적 일정의 미확인을 구분한다.

첫 버전에서 OpenAI API에 전달하는 자료는 공개 시세·기업 자료와 후보 선정 결과로 제한한다. 실제 거래 내역을 활용한 개인별 AI 복기는 별도 범위로 정한다. [AI 입력 범위 결정](adr/0001-public-data-ai.md)에 배경을 기록한다.

월 10달러를 OpenAI API 사용의 목표 한도로 잡고 사용량을 기록한다. 이 금액은 예상 요금이 아닌 설계 예산이다. 모델과 검색 횟수는 예산에 맞춰 정한다.

AI 장애나 예산 소진으로 설명을 만들지 못해도 가격·선정 조건이 정상적으로 검증됐다면 기본 보고서를 전송하고 설명이 빠진 이유를 표시한다. 일부 종목의 자료가 불충분하면 해당 종목을 보류하고, 전체 판단에 필요한 데이터가 없으면 평가 불가를 보고한다. 평가 불가와 조건 충족 후보 없음을 구분한다.

## 운영 환경

사용자가 변경을 요청하기 전까지 로컬 Mac에서 운영한다. 사용자는 특별한 상황을 제외하면 Mac을 항상 켜두지만, 실행 시각의 잠자기·전원 종료·네트워크 단절 등 예외 상황을 고려한다.

보고 시각을 놓친 뒤 정규장 개장 30분 전까지 복구되면 지연 표시와 함께 해당 날짜의 보고서를 한 번 전송한다. 그 이후에는 해당 날짜의 장전 후보 보고를 건너뛰고 누락 안내를 남긴다. Mac이 꺼져 있는 동안에는 즉시 통지할 수 없으므로 안내는 복구 후에 이루어진다.

## 텔레그램 보고서

보고서는 사용자 본인과 봇의 개인 채팅으로 전달한다. 매일 약 5분 안에 읽을 분량을 목표로 다음 순서로 구성한다.

1. 오늘의 요약과 데이터 기준 시각
2. 신규 후보 최대 3개와 가격 계획
3. 이전 후보의 주요 변화
4. 오늘의 학습 포인트 1개
5. 근거 링크와 누락·보류 사유

## 데이터 비용

첫 보고서는 추가 유료 시장 데이터 구독 없이 기존 API와 공개 자료로 시작한다. 실적 일정은 기업 IR 등 확인 가능한 근거를 사용하고, 확인하지 못하면 보류한다. 반복 자동화에 별도 서비스가 필요하면 실제 제공 범위와 가격을 조사한 뒤 사용 여부를 결정한다.

## 진행 단계

1. 실제 데이터로 만든 보고서 한 편을 검토한다.
2. 10거래일 동안 시험 운영한다. 데이터 시점, 선정 근거, 조건 누락, 정시 전달과 학습에 도움이 되는지를 점검한다. 각 후보에는 선정 이유와 계획이 무효가 되는 조건을 설명한다.
3. 실제 거래 기록은 후속 단계에서 토스증권 API로 자동 수집한다. 토스 앱에서 직접 실행한 미국 주식 거래의 조회 가능 여부와 범위는 구현 전에 검증한다.

후속 거래 기록은 미국 주식의 실제 체결 내역 전체를 수집한다. 관련 매수 후보가 있으면 연결해 보여주되, 해당 거래가 이 전략을 따른 것인지는 사용자가 표시한다.

10거래일 시험 운영은 운영·학습 품질을 점검하는 단계다. 전략의 수익성 검증 방법과 합격 기준은 별도로 정한다.

## 검증 기준

- 보고서 한 편에서 선정 결과와 가격 계산을 재현할 수 있고, 설명의 근거를 확인할 수 있어야 한다.
- 잘못된 시세, 실적 일정 미확인, AI 장애, Mac 지연을 넣었을 때 합의한 정책대로 처리해야 한다.
- 10거래일 시험 운영에서는 매일 실행 결과와 비용을 기록하고, 정상 실행 가능한 날에는 정시에 전달해야 한다.
- 사용자가 보고서를 읽고 선정 이유, 진입 보류 조건과 손실 제한 기준을 스스로 설명할 수 있어야 한다.

첫 구현의 작업 순서와 완료 범위는 [첫 보고서 구현 계획](first-milestone.md)에 기록한다.

## 토스증권 거래 기록의 확인 사항

공개 [주문 내역 문서](https://openapi.tossinvest.com/openapi-docs/latest/api-reference/Apis/OrderHistoryApi.md)와 [체결 모델](https://openapi.tossinvest.com/openapi-docs/latest/api-reference/Models/OrderExecution.md)에서 주문 조회와 주문 단위 체결 수량·평균 체결가 제공을 확인했다. 토스 앱에서 직접 접수한 주문도 조회되는지는 문서에 명시되어 있지 않아 미확인 상태다. 자동 기록의 실현 가능 여부는 기존 앱 거래의 조회 범위를 확인한 뒤 판단한다.

## 시장 데이터의 확인 사항

[토스 종목정보 문서](https://openapi.tossinvest.com/openapi-docs/latest/api-reference/Apis/StockInfoApi.md)에서 미국 거래소별 종목과 보통주 구분을 조회하는 경로를 확인했다. [KIS 시가총액 순위 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/market_cap/chk_market_cap.py)에서 시가총액·거래량·거래대금 필드를 확인했다. 실제 응답의 단위, 기준 시각과 반환 범위는 아직 검증하지 않았다.

KIS·토스의 공개 문서 조사로 향후 실적 발표 일정의 제공 경로를 확인하지 못했다. API 전체에서 해당 기능이 없다는 결론은 아니다. 보고서 한 편에서는 기업 IR 공지 등으로 일정을 확인할 수 있는지 검토하고, 반복 운영에 필요한 일정 출처와 검증 절차는 별도로 정한다. 발표 일정을 찾지 못했다는 사실을 발표 예정이 없다는 근거로 사용하지 않는다.

## 구현 전에 확인할 항목

- 실적 일정 등 데이터의 구체적인 출처, 기준 시각과 품질 확인 방법
- OpenAI 모델과 검색 범위가 월 목표 예산에 맞는지 여부
- 텔레그램 전송 결과가 불명확할 때 중복 전송을 피하는 처리 방법
- 각 지표의 계산 세부사항과 후보 경과를 관찰하는 날짜 범위

후속 실제 거래 기록 단계에서는 토스증권의 실제 체결 내역과 매수 후보를 연결하는 세부 기준을 정한다. 이 단계에서 실제 보유 종목의 기간 경과 점검·청산 기준도 별도로 다룬다.

## 학습의 출발점

일반적인 보유 기간으로 시작한다는 요청에 따라 스윙 거래를 며칠에서 몇 주에 걸친 거래로 정의한다. [Schwab의 스윙 트레이딩 설명](https://www.schwab.com/learn/story/swing-trading-strategies)이 이 기간을 뒷받침한다. 구체적인 목표 보유 기간과 기간 경과에 따른 청산 여부는 아직 정하지 않았다.
