# 단건 뉴스 수집과 AI 설명 계약

이 문서는 [#234](https://github.com/mochafreddo/swing-trading-report/issues/234)의 한 종목 설명 계약이다. 기존 [시세·선정·계산 계약](single-run-contract.md)을 유지한다. 전체 탐색과 이전 후보 경과 갱신은 이 계약의 범위 밖이다.

## 공개 근거와 시간

기업 뉴스는 기존 Micron 공식 뉴스룸의 IR 링크와 `NewsArticle`을 수집한다. 목록에서 발견한 공식 IR 기사 최대 30개를 읽고 시간대가 명시된 게시 시각이 `[자료 기준 시각 − 7일, 자료 기준 시각)`에 있는 기사만 사용한다. 목록에 다음 페이지가 있거나 한도가 넘으면 불완전한 조사로 기록한다. 시간대가 없는 게시일은 경계를 확정할 수 없으므로 확인 불가다. 실적 일정은 기존 수집 경로를 그대로 사용하며 뉴스 기간으로 제한하지 않는다.

공시는 [SEC submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)의 MU 발행인 CIK 723125와 티커를 검증하고 최근 접수 목록의 `acceptanceDateTime`에 같은 기간을 적용한다. 인증·구독은 필요 없다. 접수 유형·번호·문서 링크만 수집하며 공시 본문의 의미나 위험을 확인했다고 주장하지 않는다. SEC 조회 실패는 부분 조사로 남긴다.

수집 원문과 요청별 확인 시각은 `ExecutionRecord`가 보존한다. 뉴스 없음과 조회 실패를 구분하며 모두 위험 부재의 근거가 아니다. 뉴스 오류는 시세·실적 일정의 선정 판정을 바꾸지 않는다. 보고서에는 최대 8개 근거를 표시하고 나머지는 재현 기록에 보존한다. 이는 지정 출처의 제한된 조사이며 모든 언론 보도나 위험의 수집을 보장하지 않는다.

## AI 입력과 근거 검토

입력은 MU, 기준 시각, 코드 평가 결과의 허용 필드와 공개 근거의 허용 필드만으로 새로 구성한다. 계좌·주문·실제 거래 내역과 전체 실행 기록, 인증정보는 전달하지 않는다. 시세의 출처와 원문은 로컬 기록에 남고 AI에는 검증된 계산값과 규칙만 전달한다. 계산과 선정 결과는 AI 응답과 별도로 보존한다.

Responses API의 JSON Schema로 선정 이유, 위험 최대 3개, 계획 무효 상황, 학습 포인트 1개를 생성한다. 각 설명은 180자 이하이며 근거 ID·짧은 원문 인용·자료 기준 시각을 요구한다. 코드가 출처 존재, 기준 시각 일치, 인용문의 원문 포함 여부를 확인한다. 실패한 설명은 확인 불가로 표시하고 해당 문장을 보고서에 싣지 않는다. 코드로 의미적 함의까지 증명하지는 않으며, 인용문이 맞아도 모든 AI 서술은 `fact_verification=unconfirmed`로 기록하고 문장 바로 옆에 사실관계 확인 불가를 표시한다. AI가 작성한 사실 서술의 함의는 자동 검증하지 않으며, 확인된 사실은 코드 계산과 원문 인용으로 한정한다. AI 해석의 타당성은 사용자 검토 사항이다. 회사 자료 속 지시문은 해석 대상 자료로 취급한다.

## 호출과 비용

모델은 `gpt-4.1-mini-2025-04-14`로 고정하고 단건당 최대 1회 호출한다. 유료 검색은 0회이며 `store=false`를 사용한다. 출력은 최대 1,600토큰이고 JSON 요청은 최대 48,000 UTF-8 바이트다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini)에서 2026-10-10 확인한 100만 토큰당 입력 0.40 USD, 캐시 입력 0.10 USD, 출력 1.60 USD로 응답 사용량의 비용을 계산한다. 실제 청구서 금액과 구분한다. 월 10 USD는 예상 요금이 아닌 목표 예산이다.

모든 CLI 실행은 `runs/ai-usage/`를 공유한다. 실행 시각의 UTC 월 기준으로 파일 잠금 안에서 기존 실제 계산 비용과 미결 예약액을 합산하고 호출 한도를 예약한다. UTF-8 요청 바이트 수와 메시지 형식 여유 2,048토큰, 최대 출력으로 보수적으로 예약한다. 예약 때문에 목표 예산을 넘으면 API를 호출하지 않는다. 기존 기록은 덮어쓰지 않고 예약·정산을 각각 새 파일에 기록한다. 사용량을 알 수 없는 장애나 중단은 예약액을 유지한다. 기록이 손상되거나 잠금을 얻지 못하면 설명을 생략한다. 다른 프로그램·프로젝트의 OpenAI 사용이나 사용자가 지운 기록은 이 로컬 예산에 포함되지 않는다. 가격 변경 시 단가를 재확인해야 한다.

AI 오류·키 미설정·예산 소진·사용량 기록 실패는 이유와 함께 기본 보고서를 만든다. 필수 자료 미확인은 기존 보류 판정으로 유지한다. 자동 재시도와 새 토큰 발급은 하지 않는다. 오프라인 재현은 뉴스 응답을 다시 처리하고 공개 입력 해시·인용 검토·사용량 비용·최종 보고서를 대조하며 OpenAI 요청이나 예산 기록을 생성하지 않는다.

보고서 순서는 요약과 기준 시각, 신규 후보와 가격 계획, 이전 후보 경과, 학습 포인트 1개, 근거와 누락·보류 사유다. 단건에는 이전 후보 경과를 만들어 넣지 않는다. 약 5분 안에 읽는 목표로 본문의 근거 목록을 제한하며 전체 요청 목록은 재현 기록에서 확인한다.
