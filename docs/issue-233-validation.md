# 이슈 #233 검증 기록

## 2026-09-27 공개 출처 재확인과 공급자 확인 대기

Polestar 공식 20-F 안내에서 연결한 HTML·iXBRL 뷰어·RTF 원문을 운영 수집기의 공개 GET으로 각각 한 번 조회했다. 세 경로 모두 `network_or_encoding_error`로 실패했다. 이 오류만으로 원격 서버의 원인이나 문서 부재를 판단하지 않는다. 기존 SEC 직접 조회의 403과 함께 PSNYW의 실행 시점 근거 확인이 미완료임을 기록하며, 웹 도구로 읽은 공시를 운영 수집 성공으로 대체하지 않는다. [Polestar 공식 20-F 안내](https://investors.polestar.com/sec-filings/sec-filing/20-f/0001884082-26-000006)

Microsoft 공식 보도자료 목록의 첫 페이지는 10,478건·874페이지를 표시했다. 페이지에 공개된 WordPress API 경로에서 실적 검색을 한 번 조회했지만, 응답 본문의 envelope 내부는 `status=401`, `rest_forbidden`이었다. API의 실적 목록을 확보한 것으로 처리하지 않았으며 제한 확인 뒤 추가 API 조회는 하지 않았다. 웹 목록 첫 페이지에서 기사를 찾은 사실도 전체 공지 수집 완료를 뜻하지 않는다. 이번 응답·오류·조회 시각·성공 본문 해시는 `runs/issue233-source-access-20260927/`에 보존했다. [Microsoft 보도자료 목록](https://news.microsoft.com/source/tag/press-releases/)

사용자는 historical SIP의 체결 유일 키와 정정·취소·지연 보고 반영 범위에 대한 Alpaca의 공식 답변을 아직 받지 않았다고 확인했다. [데이터 경로 검증의 공급자 질문](issue-233-data-probe.md#취소정정-표시와-세션-조건-검증)에 기록한 계약 확인이 계속 필요하다. 답변 확보 뒤 저장 표본의 식별·정정·세션 처리를 검증하고 독립 합계를 대조해야 하며, 그 다음 조기 폐장일·20거래일·동률 순위 검증으로 진행한다. 문의는 발송하지 않았다.

이번 후속 작업은 공개 조회 결과와 대기 조건만 기록했다. 실행 코드가 바뀌지 않아 72개 테스트·64개 오류 주입 대조는 직전 구현 검증 결과를 유지하고 재실행하지 않았다. 정확 거래대금, PSNYW 자동 근거 확인, 필요한 기업 전체의 IR 지원, 거래일 장전 전체 가격 평가·소요 시간 측정은 미완료다.

## 2026-09-27 발행사 근거에 따른 비보통주 제외

사용자가 CORZZ·PSNYW처럼 발행사 공시로 보통주와 다른 권리를 확인한 종목은 원본 충돌과 근거를 보존하고 대상에서 제외하도록 승인했다. 전체 규칙 v5에 검토한 증권 유형·ISIN·영문명·공개 원문 확인 조건을 등록했다. 실행마다 목록·상세 식별과 공개 근거를 확인하며 식별 불일치, 근거 누락, 조회 실패, 미래 검토일은 보류한다. 미등록 종목에는 기존 충돌 보류를 적용한다. 원본 공급자 분류는 변경하지 않는다.

Core Scientific의 공지는 CORZZ와 CUSIP 21874A130을 보통주와 구별되는 Tranche 2 워런트로 설명한다. 직접 GET 응답과 토스의 ISIN `US21874A1300`·영문명을 대조했다. Polestar의 2025년 20-F 부속 증권 설명은 PSNYW를 Class C-1 ADS로 식별하고 Class A ADS 취득을 위한 행사 권리를 설명한다. 이 분류는 웹 도구로 읽은 공시의 검토 결과다. 운영 수집기의 같은 SEC 문서 GET은 HTTP 403이어서 PSNYW의 자동 제외 검증은 아직 통과하지 못했다. [Core Scientific 공지](https://investors.corescientific.com/news-events/press-releases/detail/81/core-scientific-announces-tranche-2-warrants-triggering-event), [Polestar 증권 설명](https://www.sec.gov/Archives/edgar/data/1884082/000188408226000006/polestarfy25formxex214de.htm)

기존 9월 27일 토스 목록·상세 응답과 이번 공개 문서 응답·오류를 조합한 오프라인 검사에서 전체 4,847종목 중 CORZZ 1종목은 제외, PSNYW를 포함한 4,846종목은 보류였다. CORZZ의 후속 가격·실적·거래대금은 조회하지 않았다. PSNYW의 미해결 충돌 때문에 `coverage_complete=false`, 휴장일로 보통주 가격 평가가 불가능하므로 전체 판정은 `held`다. 보고서·기록 재현이 일치했고 원본 토스 기록의 전후 해시가 같았다. 서로 다른 수집 시점의 저장 응답을 재분류한 검사이며 신규 전체 시장 실행이나 최신 토스 상태의 재확인은 아니다. 자료와 고정 소스는 `runs/issue233-ir-followup-20260927/`에 보존했다.

JPMorgan 목록의 2페이지는 이번 직접 조회에서 240개 항목을 반환했지만 3페이지는 여전히 404였다. 기존 연도별 목록과 이번 1·2페이지의 합집합도 577개로 선언된 579개에 못 미쳤다. 이전의 2페이지 실패 원인은 이번 성공만으로 확정하지 않는다. Microsoft 공식 기사에는 서로 다른 JSON-LD 형식이 함께 있고 기존 IR 목록은 공통 메뉴 링크를 기사로 따라가는 문제가 남아 있다. 두 경로를 수집 완료로 승격하거나 이번 변경의 운영 경로에 연결하지 않았다.

새 실행·보고서·기록·재현 검사에서 기존 구현의 충돌 보류를 먼저 확인한 뒤 공시 근거에 따른 제외를 통과시켰다. 비보통주 제외만 있고 보통주 평가가 모두 보류인 경우를 후보 없음으로 오인하는 결과도 수정 전 실패·수정 후 통과시켰다. 전체 테스트 72개와 오류 주입 대조 64개, IR·Alpaca 자체 검사, Python 구문·diff 공백 검사가 통과했다. 64개 대조는 같은 격리 환경에서 정상 구현의 통과와 변형 구현의 단언 실패를 확인했다. 설치된 정적 타입 검사기를 찾지 못해 해당 검사는 생략했고 새 도구를 설치하지 않았다.

`cf6e0b5` 대비 전체 변경과 이번 작업 트리를 규약·요구사항 두 축에서 리뷰했다. 규약 리뷰에서 IR 운영 검증 도구가 `response_too_large`를 일반 수집 실패로 바꿔 Q4 페이지 축소를 막는 호출 경로 누락을 발견했다. 실시간 수집과 재현에서 원래 오류 코드를 전달하도록 수정했다. CLI·기록·재현 경계에서 수정 전 단언 실패와 수정 후 통과를 확인하고 두 오류 전달 경로에 각각 오류 주입 대조를 추가했다. 이 검증은 합성 응답으로 수행했다. 재검토에서 규약 지적의 해소를 확인했고 새 구현 결함·범위 이탈은 없었다. 요구사항 리뷰의 기존 미완료 네 항목은 유지했다.

이 변경은 목록 유형 판정의 일부 진척이다. PSNYW 자동 근거 확인, 필요한 기업 전체의 IR 지원, 정확 거래대금·동률 순위, 거래일 장전의 전체 평가와 소요 시간 측정은 남아 있다. 이번 실행에서는 인증 파일·토큰·계정·주문을 사용하지 않았다.

## 2026-09-27 Q4 응답 크기 보완과 JPMorgan 범위 조사

Amazon 공식 IR에서 실패하던 Q4 전체 본문 페이지를 보완했다. Q4 공식 문서와 Amazon 페이지의 공개 스크립트는 0부터 시작하는 페이지 번호, 페이지 크기, 전체 본문 `bodyType=2`를 사용한다. 본문을 짧은 요약으로 대체하지 않고, 크기 초과 시 기존 페이지 시작 위치를 유지한 채 한 건씩 읽는다. 다른 HTTP·통신 오류는 재시도하지 않으며 한 건도 4 MB 상한을 넘으면 보류한다. 기존 최대 1,000건 범위와 빈 마지막 페이지 확인은 유지한다. [Q4 목록 계약](https://studioapi.q4inc.com/adhc/getpressreleaselist), [본문 유형](https://studioapi.q4inc.com/adhc/types)

실제 Amazon 실행은 다섯 번째 요청에서 크기 초과를 관측한 뒤 첫 15건 다음 위치부터 한 건씩 수집했다. 총 72회 GET으로 81개 고유 공지 본문과 마지막 빈 페이지를 확인했고, 수집·오프라인 재현을 포함한 실행 시간은 58.554초였다. 결과는 기존 `failed`에서 `complete`·`next_confirmed_earnings_not_found`로 바뀌었다. 다음 확정 일정이나 후보 선정의 성공을 뜻하지 않는다. 응답·오류·시각·해시·고정 소스와 재현 결과는 `runs/issue233-amazon-ir-20260927/`에 보존했다. 공식 Q4 스크립트는 `runs/issue233-q4-contract-20260927/`에 보존했다.

JPMorgan 공식 IR 목록의 공개 스크립트에서 동적 JSON 경로를 확인했다. 첫 페이지는 전체 579건·페이지 크기 240·최대 3페이지를 선언하지만 2·3페이지는 각각 HTTP 404였다. 화면에 제공된 2013~2026년의 14개 연도 필터를 모두 조회해 574개 고유 항목을 확인했다. 연도 필터에 없는 일반 첫 페이지의 3개 항목을 더해도 577개로 선언된 총건수보다 2개 적었다. 현재 목록의 연도 필터가 조사에 사용한 설정과 같음도 확인했다. 전체 범위 미확보이므로 이 우회 조회를 운영 수집기의 완료 경로로 연결하지 않았다. 원문과 대조 기록은 `runs/issue233-jpm-ir-20260927/`에 보존했다. [JPMorgan 공식 IR 목록](https://www.jpmorganchase.com/ir/news)

목록 충돌에 대해서는 Core Scientific의 공식 2026년 공시와 발행사 공지가 CORZZ를 보통주 CORZ와 구별되는 워런트로 명시함을 추가 확인했다. 이는 토스 분류 충돌의 원인을 판단하는 근거이며 토스 API 응답이 정정되었다는 뜻은 아니다. PSNYW의 C-1 ADS 권리와 토스 유형별 누락은 계속 확인 대상이다. [Core Scientific 공시](https://investors.corescientific.com/sec-filings/all-sec-filings/content/0001628280-26-013305/core-20251231.htm), [CORZZ 행사 공지](https://investors.corescientific.com/news-events/press-releases/detail/81/core-scientific-announces-tranche-2-warrants-triggering-event)

이번 실행은 공개 IR 자료만 사용했다. 인증 파일 조회·토큰 발급·장전 전체 가격 평가·Alpaca 추가 체결 조회는 하지 않았다. 현재 시각은 9월 27일 일요일이므로 실제 장전 전체 평가는 실행하지 않았다. 정확 거래대금은 기존 식별자·정정·지연 보고 계약과 독립 합계 검증이 계속 필요하다. 다음 단계는 거래일 장전 가격 평가로 필요한 기업을 특정하고, 확인된 목록·IR 범위 문제와 정확 거래대금 검증을 마치는 것이다.

전체 테스트 69개와 오류 주입 대조 55개가 통과했다. 새 테스트 두 개는 보고서·record.json·오프라인 재현 경계에서 기존 구현의 단언 실패와 수정 후 통과를 확인했다. 오류 주입은 같은 격리 환경에서 정상 구현의 통과와 변형 구현의 단언 실패를 확인했다. Python 구문 검사와 diff 공백 검사도 통과했다. 정적 타입 검사기가 설치되어 있지 않아 해당 검사는 생략했다.

시작 커밋 `cf6e0b5`부터 이번 작업 트리까지의 변경 전체를 규약·요구사항 두 축의 별도 에이전트가 검토했다. 규약 위반·수정이 필요한 코드 냄새·새 구현 결함·범위 이탈은 각각 0건이었다. 목록 정합성, 필요한 기업 전체의 IR 지원, 정확 거래대금·동률 정렬, 거래일 장전 전체 실행의 기존 미완료 조건 4건은 유지한다.

## 2026-09-27 최신 목록 대조와 IR 페이지 탐색 보완

사용자가 지정한 집 연결에서 토스·KIS 토큰 발급과 인증 조회에 성공했고, 별도 저장 승인 후 기존 비공개 파일에 저장했다. 저장된 값의 일치, 기존 발급용 키 보존과 소유자 전용 권한을 확인했다. 이번 목록 수집은 저장한 토큰을 재사용했으며 추가 발급은 하지 않았다. 토큰 만료 시각 관리와 자동 갱신은 구현하지 않았다.

현재 소스를 고정한 실제 실행에서 토스 일반·유형별 목록 6회, 달력 1회, 전체 상세 25회로 4,847종목을 기록했다. 총 32회 GET, 26.244초이며 원래 코드의 보고서·record.json을 오프라인으로 재현했다. 2026-09-27은 정규장이 없어 전 종목이 보류됐고 가격·IR·거래대금은 조회하지 않았다. 이 실행은 최신 목록·상세 범위의 증거이며 새 수집 순서의 전체 가격 평가나 장전 실행 완료 증거가 아니다.
