# 한 종목 평가 실행

MU 한 종목의 공개 자료를 자동 수집하고 로컬 보고서와 재현 기록을 만드는 개발 검증입니다. 전체 종목군 탐색과 첫 마일스톤 완료를 의미하지 않습니다. 계산 규칙과 미검증 항목은 [데이터·계산 계약](single-run-contract.md)을 확인하세요.

Python 3.14에서 저장소 루트를 작업 디렉터리로 사용하세요. 실행 코드에는 표준 라이브러리만 필요합니다. Python과 검증 도구는 [mise 설정과 CI 안내](ci-design.md#로컬-검증)에 따라 준비하세요.

## 인증정보 준비

[환경변수 틀](../.env.example)을 저장소와 동기화 폴더 밖의 비공개 파일에 복사하세요. 다음 예시는 사용자 로컬 데이터 디렉터리를 사용합니다. 이미 파일이 있다면 덮어쓰지 마세요.

```sh
mkdir -p "$HOME/.local/share/swing-trading-report"
(umask 077; set -C; cat .env.example > "$HOME/.local/share/swing-trading-report/credentials.env")
```

파일의 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`, `KIS_APP_KEY`, `KIS_APP_SECRET`를 채우세요. 기존 토큰을 사용할 때는 `TOSS_ACCESS_TOKEN`, `KIS_ACCESS_TOKEN`도 채우세요. 파일은 소유자만 읽고 쓸 수 있는 권한 `600`이어야 합니다. 실제 값은 저장소의 `.env.example`, 채팅, 명령 인자에 넣지 마세요.

값은 그대로 읽으며 셸 명령이나 환경변수를 확장하지 않습니다. 파일을 지정하지 않으면 동일한 이름의 프로세스 환경변수를 읽습니다. 자격 증명은 API 요청 헤더와 토큰 요청 본문에서만 사용하며 보고서·재현 기록에 저장하지 않습니다. 계좌·보유·주문 API는 사용하지 않습니다.

## 단건 수집

기존 토큰이 있으면 다음과 같이 실행하세요. `--output`에는 존재하지 않는 새 디렉터리를 지정하세요.

```sh
python3 single_run.py run \
  --credentials-file "$HOME/.local/share/swing-trading-report/credentials.env" \
  --output runs/mu-first
```

키만 있고 토큰이 없으면 위 명령에 `--issue-tokens`를 추가하세요. 이 옵션은 토스와 KIS 토큰 발급 API를 각각 한 번 호출하고 응답 토큰을 현재 프로세스의 메모리에만 보관합니다. 토스는 기존 토큰을 즉시 무효화하며, KIS 공식 예제는 토큰 발급 시 알림톡이 발송된다고 설명합니다. 다른 프로그램의 토스 토큰 사용 여부를 확인한 뒤 명시적으로 실행하세요. 실패하면 자동 재발급하거나 재시도하지 않습니다. 실패 메시지에는 서비스명과 HTTP 상태 또는 통신·응답 형식 오류, 실패 전에 성공을 확인한 서비스(`confirmed_before_failure`)만 표시합니다. `none`은 실패한 요청이 서버에서 토큰을 발급하지 않았다는 보장이 아닙니다. 발급 응답을 받지 못한 경우의 서버 상태는 미확인으로 남기세요.

보고일은 기본적으로 현재 미국 동부시간 날짜입니다. `--report-date YYYY-MM-DD`로 지정할 수도 있지만 해당 날짜의 장전 자료가 아니면 평가를 보류합니다. 과거 날짜의 판단을 확인하려면 아래 재현 명령을 사용하세요.

출력의 `report.md`는 사람이 읽을 보고서이고 `record.json`은 수집 응답·출처·조회 시각·규칙·결과를 보존합니다. `runs/`는 Git에서 제외됩니다. 종료 코드 `0`은 선정 또는 검증된 조건 탈락, `2`는 평가 보류, `1`은 실행·인증·재현 실패입니다. `2`를 실제 시세 연동 완료로 해석하지 마세요.

KIS 원주가를 Yahoo 정규장 일봉과 대조하고, 거래량은 Yahoo 일봉 계열을 사용합니다. 현금배당은 가격에 소급 조정하지 않으며, 평가 구간 시작일부터 보고 당일까지 분할이 있으면 보류합니다. 거래대금은 KIS 정규장 분봉에서 확인된 금액의 하한으로 유동성 통과만 확인합니다. 하한이 5,000만 USD 미만이면 전체 금액을 알 수 없으므로 탈락 대신 보류합니다. 출처·날짜·시각·가격·분봉에 누락이나 불일치가 있어도 보류하며 검증을 우회하는 옵션은 없습니다. 인증정보 없이도 공식 뉴스룸·IR 수집은 시도하고 부족한 항목을 기록합니다.

2026-09-11 실제 자료에서는 돌파·거래량 조건 미충족으로 MU가 제외되었습니다. 앞선 보류 원인과 새 수집 경로의 단위·세션·기업행사 처리 근거는 [검증 기록](issue-232-validation.md)을 참고하세요. 거래대금 하한은 정확한 전시장 평균이나 후보 간 동순위 비교값으로 사용할 수 없습니다.

## 오프라인 재현과 검증

```sh
python3 single_run.py replay runs/mu-first
mise run test
mise run negative-controls
mise run lint
```

재현은 네트워크·인증정보 없이 보존된 응답을 다시 처리합니다. 원래 코드 버전과 규칙이 일치해야 하며 자료 또는 보고서가 바뀌면 실패합니다. SHA-256은 우발적인 변경을 확인하는 무결성 검사로, 작성자 인증 서명이 아닙니다. 기존 기록은 덮어쓰지 않습니다.

검증용 사례는 실제 API 응답과 같은 경계에 합성 자료를 넣어 단건 실행 전체를 확인합니다. 오류 주입 검증은 임시 복사본에서 정상 구현과 일부러 잘못 만든 구현에 같은 테스트를 실행합니다. 각 오류에 대해 정상 구현의 종료 코드가 `0`, 잘못된 구현의 종료 코드가 `1`이고 단언 실패가 확인되어야 합니다. 문법 검사는 정적 타입 검사를 대신하지 않습니다.

## 뉴스와 AI 학습 설명

뉴스·공시는 자료 기준 시각 직전 7일을 자동 조사합니다. 실적 일정 확인은 이 기간과 별도로 유지됩니다. 조사 범위와 설명의 사실 검토 한계, 월 목표 예산은 [설명 계약](report-explanation-contract.md)을 확인하세요.

OpenAI 키가 없거나 AI 장애·예산 소진이 발생해도 보고서에는 원래 선정 결과와 누락 사유가 남습니다. 키는 `OPENAI_API_KEY` 환경변수로 전달하거나, 소유자만 읽고 쓸 수 있는 파일을 `--ai-key-file`로 명시하세요. 예를 들어 사용자가 직접 준비한 Git 제외 파일 `.env`의 키를 사용할 때는 다음과 같이 실행합니다. 시장 데이터 인증 파일은 기존 정책대로 저장소 밖에 두세요.

```sh
python single_run.py run \
  --credentials-file "$HOME/.local/share/swing-trading-report/credentials.env" \
  --ai-key-file .env \
  --output runs/mu-with-explanation
```

키 값은 채팅·명령 인자·보고서에 넣지 마세요. 키 파일의 권한은 `600`이어야 합니다. AI에는 공개 근거와 선정 결과의 허용 필드만 전달됩니다. 원문 인용의 일치와 기준 시각은 확인하지만 AI 설명의 사실관계는 확인 불가로 표시합니다. 확인된 가격과 선정 판정은 보고서의 코드 계산 결과를 기준으로 검토하세요.

실행당 OpenAI 요청은 최대 1회이고 유료 검색은 사용하지 않습니다. 비용 기록은 `runs/ai-usage/`에 공유하며 기록을 지우거나 실행 작업 디렉터리를 바꾸면 같은 월의 누적 사용량을 유지할 수 없습니다. 출력 토큰과 공개 단가로 계산한 비용은 실제 청구서와 구분하세요. 월 10 USD는 예상 요금이 아닌 목표 예산입니다. 통신 실패·중단으로 사용량이 불명확하면 예약액을 유지하며 자동 재시도하지 않습니다.

재현에는 OpenAI 키가 필요하지 않으며 새 생성 요청이나 비용 기록도 만들지 않습니다. 기존 기록은 코드 버전 검증 때문에 현재 구현과 섞어 재현할 수 없습니다.
