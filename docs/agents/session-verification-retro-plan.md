# 세션 검증 환경 개선 설계

이번 회고의 네 권고안을 구체화하는 작업 문서다. 사용자가 `implement`로 승인한 설계와 그 구현·검증 기록이다.

## 확정한 범위

2026-10-10 사용자 답변으로 다음 세 결정을 확정했다.

- 프로젝트별 오류 주입 검사는 이 저장소에서 관리하고 공통 실행 절차는 사용자가 관리하는 문서에서 수정한다. 외부에서 가져온 스킬은 원문을 유지한다. 프로젝트 검사와 공통 절차를 같은 곳에 중복 정의하지 않는다.
- 포맷·린트와 영향받는 테스트를 통과시킨 뒤 검증할 소스를 고정한다. 그 이후 독립적인 읽기 전용 검사는 병렬로 실행할 수 있다. 코드가 바뀌면 관련 검사 결과를 무효화하고 재검증하며, 수정 후 재검증은 전체 테스트 한 번 제한의 예외다.
- 기본 출력은 필요한 범위로 제한하되 장시간 작업의 세션 ID·종료 코드와 검증 로그를 보존한다. 이슈는 제목·상태·본문부터 읽고 필요한 댓글을 추가 조회한다. 상세 로그는 비밀값을 제외한 소유자 전용 임시 파일에 남긴다. 새 범용 CLI보다 기존 도구와 호출 절차를 보완한다.

## 확인한 기존 경로

`mise.toml`과 `.github/workflows/ci.yml`은 린트·전체 테스트·기존 오류 주입 검사를 이미 실행한다. `check_negative_controls.py`는 정상 사본 통과와 변이 사본의 단언 실패를 확인한다. 설계 당시 새 회귀 테스트는 발견됐지만 임시 도구로 검증한 변이 9개는 정규 오류 주입 목록에 없었다. 이번 구현은 기존 목록에 이 9개를 등록한다.

공유 역할 확인 절차에는 `verify_agent_selection.py`가 이미 있다. 정확한 부모 세션·에이전트 경로·역할을 세션 헤더와 대조한다. 역할 선택 확인은 실제 모델·추론 강도·권한 검증과 구분한다. 회고 중 이 도구로 Spec 리뷰어의 역할 선택은 확인했으나 구현 당시 실행한 확인은 아니었다.

## 오류 주입과 역할 확인

사용자는 추가 질문에도 권고안을 선택했다. 새 변이 9개는 기존 검사에 편입한다. 정상 사본은 통과하고 변이 사본은 의도한 동작을 확인하는 단언에서 실패해야 한다. 앵커 불일치·실행 실패·관련 없는 예외는 성공으로 세지 않는다. 임시 검사에서 예외로 끝난 사례는 기존 회귀 테스트를 보강하며, 중복 가드로 살아남는 변이는 실제 경계에 맞춰 다시 정의한다.

검증할 경계는 요청 전 마감, 반환 후 마감, 요청 간 대기 이후 HTTP 차단, 준비 시각 일관성, 준비·발행의 결합, 달력 미확보 시 미전송, IR 검토 대상, 지연 캡션 수정과 재전송 방지, 저장 이후 요청 직전의 복구 시한 재확인이다.

역할 확인 도구는 호출 직후 실행하고, 메타데이터 미확보이면 첫 응답 이후 한 번 재확인한다. 계속 미확인이면 `dispatched-unverified`로 기록하고 작은 읽기 전용 조사만 허용한다. 역할 설정에 의존하는 쓰기와 권한 분리 작업은 보류한다. 역할 불일치는 실패로 처리한다. 역할 선택·실제 모델·추론 강도·권한의 확인 상태는 각각 보존한다.

## 관리 위치와 검증 경로

`dispatching-custom-agents`와 확인 도구는 dotfiles 저장소가 관리한다. 기존 `tests/test_codex_agent_selection.py`는 역할 일치·불일치·부재, 부모와 경로 불일치, 중복 일치, 손상 헤더와 본문 비노출을 검사한다. 실제 모델·추론 강도·권한 검증은 이 도구의 기능이 아니다.

`~/.agents/skills/implement/SKILL.md`는 심볼릭 링크가 아닌 머신 로컬 파일이며 확인한 Git 저장소에서 관리하지 않는다. 사용자는 mattpocock 스킬처럼 외부에서 가져온 스킬을 수정하지 않는다고 정정했다. 따라서 이 파일과 다른 외부 스킬은 편집하지 않는다. 검증 순서와 실행 결과 보존 절차는 직접 관리하는 기존 문서와 연결 지점에서 다룬다. 공통 검증의 기존 기준은 dotfiles의 `.codex/AGENTS.md`에 있는 Verification 절이다. 역할 확인 스킬과 검사기는 dotfiles에서 관리하며 저장소 설명과 작성 이력은 사용자 관리 문서임을 뒷받침한다. 외부 구현 스킬은 변경 범위에서 제외한다.

구현 완료는 프로젝트의 린트·회귀 테스트·전체 검사와 9개 변이의 정상 통과/단언 실패, 사용자 관리 문서의 의미·링크·보존 범위 리뷰, 기존 역할 선택 검사와 실제 세션 헤더 확인 결과로 판단한다. 문서의 특정 문구를 고정하는 테스트는 추가하지 않는다. 실제 에이전트 자동 호출이나 권한 강제 여부를 시험하지 않았다면 해당 검증을 생략한 것으로 명시한다.

## 최종 변경 범위

사용자는 공통 검증 순서와 실행 결과 보존을 dotfiles의 기존 `.codex/AGENTS.md` Verification 절에 최소한으로 추가하는 권고안을 선택했다. 역할 확인은 사용자가 관리하는 `.codex/skills/dispatching-custom-agents/SKILL.md`의 기존 절차를 보완한다. 외부 `implement`를 비롯한 외부 스킬과 새 범용 도구는 변경·추가하지 않는다.

프로젝트에서는 `check_negative_controls.py`에 새 변이 9개를 편입하고 필요한 기존 회귀 테스트를 보강한다. dotfiles에서는 검증 순서·실행 결과 보존·역할 확인 절차만 수정한다. 기존 CI 연결은 유지하고 같은 검사를 새 체계로 중복 구현하지 않는다.

## 완료 기준

- 새 변이 9개 모두 기존 검사 절차에서 정상 사본 통과와 의도한 단언 실패를 보여야 한다. 오류 주입 목록과 테스트의 경계 대응이 설명되어야 한다.
- 영향받는 테스트와 포맷·린트 이후 소스를 고정하고 최종 전체 검사를 실행한다. 이후 수정이 있으면 관련 결과를 무효화해 다시 검증한다. 테스트 결과와 실행 대상이 일치해야 한다.
- 역할 확인은 기존 검사기와 테스트를 재사용한다. 일치·불일치·부재·중복·손상 메타데이터를 구분하고, 실제 세션 헤더 확인은 역할 선택의 증거로만 기록한다. 실제 모델·추론 강도·권한을 확인하지 않았다면 미확인으로 남긴다.
- 장시간 호출의 세션 ID·종료 코드·로그 위치를 보존하고 사용자가 읽는 출력은 필요한 결과로 제한한다. 외부 스킬의 변경이 없어야 한다. 지침은 의미와 연결 경로를 리뷰하며 특정 문구를 고정하는 테스트는 만들지 않는다.
- 두 저장소의 변경과 검증, 생략한 검사, 역할 확인 범위를 구분해 보고한다. 이번 설계는 #233의 실제 데이터 완료 조건을 충족했다는 근거가 아니다.

## 합의 상태

개별 설계 결정은 모두 확정했고 사용자는 `implement`로 전체 구현을 승인했다. 검증 결과는 아래 구현 기록에 추가한다.

이번 변경은 되돌리기 쉬운 검증 절차 개선이므로 ADR을 만들지 않는다. 일반적인 검증·도구 용어를 트레이딩 도메인 용어집에 추가하지 않는다.

## 구현·검증 결과

프로젝트 기준 커밋은 `4e26d3cedd7a4bc5efba92ece2b08a7f4a2bb44b`, dotfiles 기준 커밋은 `75bf963023411d87a4709c66fa088c7e69ad7281`이다. 프로젝트는 기존 오류 주입 목록과 두 공개 경계의 테스트만 변경했다. dotfiles는 사용자 관리 지침 두 파일만 변경했다.

- `MISE_AUTO_INSTALL=0 mise run lint`: Ruff·포맷·actionlint 통과.
- 영향받는 전체 실행·전송 테스트 63개와 기존 역할 선택 검사 7개 통과.
- `MISE_AUTO_INSTALL=0 mise run test`: 전체 테스트 152개와 Alpaca·IR 프로브 자체 검증 통과.
- `MISE_AUTO_INSTALL=0 mise run negative-controls`: 기존 121개와 새 9개, 총 130개 모두 정상 사본 통과·변이 사본의 단언 실패를 확인했다. 새 9개는 편입 전에도 `mutation-probe.py`로 같은 정상/변이 절차를 실행했다. 반환 후 마감은 먼저 결과를 확인한 뒤 재현하도록 테스트를 보강했고, 누락 캡션 상태는 예외 대신 상태 단언으로 확인한다. 달력 없는 전송 변이는 시도 시각을 달력 시한으로 대체하는 오류를 주입해 전송 함수 미호출 단언이 실패함을 확인한다.
- dotfiles의 `zsh tests/run.sh`: 33개 묶음 중 32개 PASS, maxfiles 묶음은 샌드박스의 읽기 전용 sudo 상태 확인 차단으로 PARTIAL이었다. 해당 묶음을 샌드박스 밖에서 `python3 -B tests/test_maxfiles_daemon.py`로 재검증했고 11개 테스트가 통과했다. 전체 실행의 PARTIAL 기록과 별도 재검증 결과를 구분한다. 관리자 권한을 획득하거나 인증 상태를 갱신하지 않았으며 설치 동작은 임시 파일·가짜 명령으로 검사했다.
- 최종 검사 전후 변경 소스 5개의 SHA-256이 일치했다. 실행 명령·작업 디렉터리·세션 ID·종료 코드·상세 로그는 소유자 전용 임시 기록에 보존했다.
- 확인한 외부 스킬 7개(`implement`, `tdd`, `code-review`, `grilling`, `domain-modeling`, `writing-for-agents`, `grill-with-docs`)의 `SKILL.md` 해시가 전후 일치했다.

### Standards

독립 읽기 전용 리뷰에서 문서의 승인·구현 상태 표현을 수정한 뒤 남은 지적 사항은 없다. 소스·문서 리뷰이며 reviewer가 테스트를 실행했다는 근거는 아니다.

### Spec

독립 읽기 전용 리뷰에서 변이 9개, 공개 검증 경계, 소스 고정·결과 보존·역할 확인 절차가 승인 범위와 일치함을 확인했다. 문서 상태 표현을 수정한 뒤 남은 지적 사항은 없다.

두 reviewer의 역할 선택은 기존 세션 헤더 확인 도구로 `verified`를 확인했다. 실제 모델·추론 강도·권한 강제는 확인하지 않았다. 이번 호출은 이미 선택된 에이전트를 재사용했으므로 새 호출에서 메타데이터가 늦게 생기는 경우의 자동 재확인 동작은 검증하지 않았다. 그 분기는 지침의 의미 검토와 기존 검사기의 메타데이터 부재 검사로 확인한 범위다.

mypy·pyright가 설치되어 있지 않아 정적 타입 검사는 생략했다. 실제 시세·Telegram 전송이나 #233의 실제 데이터 완료 조건은 이번 작업의 검증 대상이 아니다. 외부 스킬 원문과 새 범용 CLI는 변경하지 않았다.
